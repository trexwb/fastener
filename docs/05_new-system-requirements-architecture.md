## 1. 市场趋势与竞争态势

### 1.1 行业规模

| 维度 | 数据 |
|------|------|
| 全球市场规模（2024） | 893.4 亿美元，预计2032年达 1258.7 亿美元，CAGR 4.3% |
| 中国市场规模（2024） | 1593.1 亿元人民币 |
| 中国市场增速（2025-2030） | 预计保持 4%~5% 中速稳定增长 |
| 中国出口额（2024） | 114.74 亿美元，全球最大生产国与出口国 |
| 高端紧固件国产化目标 | 2025年提升至 85%（2023年为72%） |

### 1.2 结构性趋势（三大增长引擎）

```
传统需求萎缩（建筑）
      ↓
新兴需求爆发：
  ├── 新能源汽车：轻量化 + 高电压安全连接
  ├── 风电/光伏：极端工况耐腐蚀、25年+长寿命
  ├── 人形机器人：精密 + 轻量化 + 高可靠性（新蓝海）
  └── 高铁/特高压：高强度标准件深度国产化
```

### 1.3 数字化现状（哑铃型结构）

| 企业层级 | 占比 | 现状 |
|---------|------|------|
| 头部企业 | 5%~10% | 自动化立库、5G+工业互联网、黑灯工厂 |
| 腰部企业 | 10%~20% | ERP/MES已部署，但数据孤岛严重 |
| **尾部企业** | **70%~80%** | **纸质记录为主，数字化水平极低** |

> 📌 **关键洞察**：70-80% 的企业仍停留在纸质阶段——这意味着数字化工具的渗透空间巨大，**门槛低的轻量化 SaaS 是切入尾部企业的最优路径**。

### 1.4 竞争格局分析

| 玩家类型 | 代表产品 | 优势 | 劣势 |
|---------|---------|------|------|
| 综合 B2B 平台 | 1688、百度爱采购 | 流量大、SKU多 | 无行业纵深，服务浅 |
| 垂直信息平台 | 华人螺丝网 | 行业积累久，内容资源 | 交易能力弱，工具缺失 |
| 一站式采购商城 | 工品一号、工业熊 | 有自营仓，履约强 | 无技术/工程服务 |
| 国际平台 | Fasten.it | 全球 80 国 | 中文弱，不懂GB标准 |
| **市场空白** | — | — | **没有一个平台同时做到：行业工具 + 交易撮合 + 技术服务** |

## 2. 目标用户画像与痛点分析

### 2.1 三类核心用户

#### 👷 用户 A：企业采购工程师（应用端）

**画像**：机械/制造企业负责紧固件选型与采购的工程师，日均处理数十条询价单，在多个平台和供应商之间反复沟通。

| 场景 | 痛点 |
|------|------|
| 选型 | 规格繁杂（DIN/ISO/GB 混用），手册翻阅慢，选错型号导致返工 |
| 询价 | 电话/微信询价效率低，比价困难，价格不透明 |
| 质检 | 收货后无法快速核验，假冒伪劣难识别，批次追溯困难 |
| 库存 | 备货靠经验，要么积压要么断货，资金占用高 |
| 管理 | 采购流程繁琐，对账、归档手工操作量大 |

**核心诉求**：给我一个工具，让我**10分钟内完成：选型 → 找货 → 比价 → 下单**。

---

#### 🏭 用户 B：紧固件生产厂家

**画像**：年产值 500万~5000万的中小型紧固件制造商，客户主要靠老关系维系，数字化基础薄弱。

| 场景 | 痛点 |
|------|------|
| 获客 | 渠道单一，深度依赖老客户和展会，线上触达新客户能力为零 |
| 展示 | 产品目录 PDF、纸质规格表，无法在线快速更新 |
| 定制接单 | 来图定制需求处理全靠人工邮件往来，效率低，易丢单 |
| 生产计划 | 插单频繁，交期波动，准交率低，客户投诉多 |
| 资金 | 原材料现金采购，货款回收慢，现金流压力大 |

**核心诉求**：给我一个**展示窗口 + 在线接单能力**，让新客户找到我、老客户留住我。

---

#### 🚚 用户 C：专业贸易商/经销商（流通端）

**画像**：持有一定库存、服务多家终端客户的紧固件经销商，核心价值在于快速响应和配套服务。

| 场景 | 痛点 |
|------|------|
| 库存管理 | SKU 数千，手工记账，库存不准，漏单/错单频发 |
| 报价 | 临时查价、现场估算，客户等待时间长，丢单率高 |
| 被替代风险 | 平台直连工厂趋势下，纯信息中介价值被压缩 |
| 货源整合 | 非主营规格临时调货渠道不稳定，影响客户交期 |

**核心诉求**：帮我管好库存，让我报价更快，让客户离不开我。

---

### 2.2 用户优先级排序

```
第一优先：企业采购工程师（最大用户基数，付费意愿强，工具需求明确）
第二优先：紧固件生产厂家（供给侧，决定平台商品丰富度）
第三优先：专业贸易商（流通效率放大器，特定场景高价值）
```

## 3. 系统定位与核心价值主张

### 3.1 系统定位

> **扣环（COUPLER）** — 紧固件行业全链路数字化服务平台
> 
> 连接**采购商、供应商、工程师、贸易商**四类节点，  
> 打通**选型 → 询价 → 交易 → 质检 → 管理**全链路，  
> 覆盖**GB / ISO / DIN / ANSI** 四套国际标准体系。

### 3.2 核心价值主张（分用户）

| 用户 | 核心价值 |
|------|---------|
| 采购工程师 | **从2小时选型+询价，缩短到15分钟** |
| 生产厂家 | **从零到有的线上展示和在线接单能力** |
| 贸易商 | **库存数字化 + 智能报价，提升服务响应速度 2 倍** |

### 3.3 与竞品的差异化

```
竞品 A（1688/爱采购）：有流量，无技术服务，选型困难
竞品 B（华人螺丝网）：有内容，无交易闭环，无工具
竞品 C（工品一号）：  有履约，无标准库，无工程支持

扣环 COUPLER：
├── 标准库深度（GB/ISO/DIN/ANSI 全覆盖）[内容护城河]
├── 工程工具（选型计算器、强度校验、重量估算）[工具护城河]
├── 交易闭环（询价→报价→订单→支付→物流）[业务闭环]
└── 来图定制（图纸解析 + 非标快速报价）[高价值服务]
```

## 5. 核心业务流程设计

### 5.1 标准采购闭环（主流程）

```
[采购工程师]
     │
     ├─ ① 规格确认 → 标准件库检索 → 确认产品型号
     │
     ├─ ② 发起询价 → 选择供应商（平台推荐/自有供应商）→ 发送 RFQ
     │
     ├─ ③ 供应商报价 → 平台比价视图 → 选定供应商 → 确认报价
     │
     ├─ ④ 生成订单 → 合同确认 → 线上支付（或账期结算）
     │
     ├─ ⑤ 物流跟踪 → 到货通知
     │
     └─ ⑥ 质检验收 → 确认收货 → 评价供应商
```

### 5.2 来图定制闭环

```
[采购工程师]
     │
     ├─ ① 上传图纸（DXF/STEP/PDF）+ 填写材料要求
     │
     ├─ ② 平台分发至匹配供应商（按能力标签智能匹配）
     │
     ├─ ③ 供应商竞报价（24-72h 内报价）
     │
     ├─ ④ 比较报价 → 选定供应商 → 打样确认
     │
     └─ ⑤ 样品确认 → 批量订单 → 执行采购闭环
```

### 5.3 供应商侧运营闭环

```
[供应商/厂家]
     │
     ├─ ① 入驻 → 填写能力标签 → 上传产品目录
     │
     ├─ ② 接收 RFQ → 在线报价 → 订单确认
     │
     ├─ ③ 发货 → 录入物流单号 → 上传发货单
     │
     └─ ④ 收款确认 → 评价买家 → 积累信用评分
```

## 6. 数据库 E-R 设计思路

### 6.1 核心实体

```
核心实体（Entity）
│
├── User（用户）
│   ├── id, email, phone, name
│   ├── role: ENUM(buyer, supplier, trader, admin)
│   └── enterprise_id → Enterprise
│
├── Enterprise（企业）
│   ├── id, name, type: ENUM(manufacturer, trader, buyer)
│   ├── certifications: JSON(认证列表)
│   ├── capability_tags: JSON(产品能力标签)
│   └── credit_score: DECIMAL
│
├── Standard（标准文件）
│   ├── id, code（如 GB/T 5782）, name
│   ├── standard_body: ENUM(GB, ISO, DIN, ANSI, JIS)
│   ├── version, publish_date
│   └── pdf_url
│
├── FastenerSpec（紧固件规格定义）
│   ├── id, standard_id → Standard
│   ├── type: ENUM(bolt, nut, screw, washer, pin...)
│   ├── material: ENUM(碳钢, 不锈钢, 合金钢, 铜, 铝...)
│   ├── grade（强度等级：4.8/8.8/10.9/A2-70...）
│   ├── surface: ENUM(镀锌, 发黑, 达克罗, 磷化...)
│   ├── thread_profile: JSON(螺纹参数：d, p, As...)
│   ├── dimensions: JSON(头部/杆部/螺纹各段尺寸)
│   └── tolerance_class（公差等级）
│
├── Product（供应商商品）
│   ├── id, supplier_id → Enterprise
│   ├── spec_id → FastenerSpec（关联标准规格）
│   ├── sku_code, brand
│   ├── price_tiers: JSON([{qty_min, qty_max, unit_price}])
│   ├── stock_qty, lead_time_days
│   ├── certifications: JSON
│   ├── drawing_2d_url, drawing_3d_url
│   └── status: ENUM(active, inactive, draft)
│
├── RFQ（询价单）
│   ├── id, buyer_id → User
│   ├── rfq_no（系统编号）
│   ├── items: JSON([{spec_id/product_id, qty, unit, note}])
│   ├── delivery_date_required
│   ├── status: ENUM(draft, sent, quoting, closed)
│   └── created_at
│
├── Quote（报价单）
│   ├── id, rfq_id → RFQ
│   ├── supplier_id → Enterprise
│   ├── items: JSON([{product_id, qty, unit_price, total}])
│   ├── valid_until, delivery_days
│   ├── status: ENUM(pending, accepted, rejected, expired)
│   └── remarks
│
├── Order（订单）
│   ├── id, rfq_id → RFQ, quote_id → Quote
│   ├── order_no
│   ├── buyer_id → Enterprise, supplier_id → Enterprise
│   ├── items: JSON（锁定报价时的商品快照）
│   ├── total_amount, currency
│   ├── payment_status: ENUM(unpaid, partial, paid)
│   ├── logistics_no, logistics_company
│   └── status: ENUM(confirmed, producing, shipped, received, completed)
│
├── QualityRecord（质检记录）
│   ├── id, order_id → Order
│   ├── batch_no（批次号）
│   ├── inspector_id → User
│   ├── check_items: JSON(检验项目及结果)
│   ├── result: ENUM(pass, fail, conditional)
│   ├── report_url
│   └── action: ENUM(accept, return, rework, claim)
│
├── CustomOrder（来图定制单）
│   ├── id, buyer_id → User
│   ├── drawing_files: JSON([{url, type, filename}])
│   ├── requirements: TEXT（材料/公差/表面处理说明）
│   ├── quantity, deadline
│   ├── status: ENUM(pending, quoting, sampling, approved, producing)
│   └── matched_suppliers: JSON([supplier_id...])
│
└── Inventory（库存记录）
    ├── id, enterprise_id → Enterprise
    ├── product_id → Product（或 custom_spec_id）
    ├── warehouse_name, location
    ├── qty_in_stock, qty_reserved
    ├── reorder_threshold
    └── last_updated_at
```

### 6.2 关键关联关系

```
User ——N:1——> Enterprise
Enterprise ——1:N——> Product（供应商侧）
FastenerSpec ——N:1——> Standard
Product ——N:1——> FastenerSpec
RFQ ——N:1——> User（发起方）
Quote ——N:1——> RFQ
Order ——N:1——> Quote
QualityRecord ——N:1——> Order
CustomOrder ——N:1——> User
Inventory ——N:1——> Enterprise
```

### 6.3 关键设计决策

| 决策点 | 方案 | 理由 |
|-------|------|------|
| 规格多维度存储 | `dimensions: JSON` + 独立索引字段 | 规格参数差异大（螺栓与垫圈字段完全不同），JSON 保持弹性 |
| 价格分级 | `price_tiers: JSON` 在 Product 上 | 支持阶梯价，无需额外关联表 |
| 报价/订单快照 | `items: JSON` 锁定时间点数据 | 防止商品价格变更影响历史订单 |
| 多标准支持 | `standard_body: ENUM` + `standard_id` FK | 标准是规格的上游，一款规格属于一个标准 |
| 批次追溯 | `batch_no` 在 QualityRecord | 最小代价实现批次级质量追溯 |

### 7.2 技术栈选型

| 层次 | 技术选型 | 理由 |
|------|---------|------|
| 前端框架 | Vue 3 + TypeScript + Vite | 现有团队熟悉，生态成熟 |
| UI 组件库 | TDesign（腾讯）或 Element Plus | 工业风格，B端适配好 |
| 后端框架 | Node.js + Fastify（或 Koa 2） | 高性能 I/O，轻量，团队熟悉 Node |
| ORM | Prisma（替代 knex）| 类型安全，schema-first，迁移管理优秀 |
| 数据库 | MySQL 8.0 | 稳定，关系型适合业务复杂度 |
| 搜索引擎 | Meilisearch（轻量）或 Elasticsearch | 规格参数全文检索，中文分词支持 |
| 缓存 | Redis 7 | 热点规格缓存、Session、报价锁 |
| 文件存储 | 腾讯云 COS / 阿里云 OSS | 图纸/文档/PDF 存储 |
| 消息队列 | BullMQ（Redis-based） | 异步任务：邮件/通知/报表生成 |
| 认证 | JWT + Refresh Token | 无状态，支持多端登录 |
| 微信生态 | 微信小程序 + 企微通知 | 行业用户微信使用率极高 |
| 部署 | Docker + PM2 → 后续 K8s | 渐进式扩展，从单机走向集群 |

## 附：交互设计原则

针对紧固件行业从业者（多为 35-55 岁，偏传统工业背景）：

1. **功能优先，不炫技**：每个页面核心操作不超过 3 个，减少学习成本
2. **数字说话**：规格参数、价格、库存数量直接呈现，不隐藏在二级页面
3. **搜索为王**：首页最显著位置是搜索框，支持型号/标准号/关键词多路径搜索
4. **移动友好**：考虑到大量用户在工厂现场或仓库中操作，移动端必须体验流畅
5. **表格即界面**：工程师习惯看规格表，关键数据用表格呈现而非卡片
6. **错误可恢复**：询价/报价误操作可撤回，降低操作焦虑

# 紧固件行业数字化产品 — 需求调研总结报告

> **文档性质**：产品方向确认文件，供产品总监设计产品使用
> **调研时间**：2026-04-10
> **调研方式**：与产品经理、市场、技术专家、行业领袖多轮讨论

---

## 一、产品定位

### 1.1 起点定位（0-18个月）

> **「紧固件从业者的标准知识库——数据经专业校正，每条标准附专家解读」**

用户来这里不是因为「能查」，而是因为「能查到对的，还能看懂为什么对」。

### 1.2 终极愿景（18个月+）

> **「紧固件行业从选型到交付的全链路数字化工作台」**

涵盖服务、贸易、指南、交易、生产管理等全链路数字化。

### 1.3 定位逻辑

| 竞品（易紧通、华人螺丝、工品一号） | 我们 |
|---|---|
| 数据多，常用标准覆盖 | 数据准，**经过专业人员逐条核实纠正** |
| 用户自己判断对错 | 用户拿到**专家解读**，知道哪里有坑、怎么避坑 |
| 查完即走，无回访价值 | 专家内容形成知识壁垒，用户持续回访 |

## 二、核心差异化来源

> **这是整个产品的基础，是其他一切无法复制的根本原因。**

### 2.1 专家合伙人制

行业内公认的深度专家，具备以下能力：

| 能力 | 商业价值 |
|---|---|
| 逐条吃透 GB/ISO/DIN 标准，识别参数错误和实际生产中的不可行项 | 建立行业标准本身，而非搬运标准 |
| 联合生产企业申报企业标准、新标准 | 形成数据壁垒，竞品 2-3 年无法复制 |
| 提供最合适的替代方案（当原标准成本过高或不可行时） | 直接解决采购/工程师的实际问题 |
| 编写装配指南、施工避坑说明 | 覆盖用户现场操作的真实需求 |

### 2.2 数据与内容的双重壁垒

| 壁垒类型 | 说明 |
|---|---|
| **数据壁垒** | 标准参数经过专业纠正，部分已申请国标/企标，数据本身受保护 |
| **知识壁垒** | 专家解读、装配说明、避坑指南是持续产出的内容，无法批量复制 |
| **供应链壁垒** | 贸易业务积累了大量供应商和需求方匹配经验，知道哪些供应商能生产特定标准 |

### 2.3 需求解析与供应匹配能力

竞品做不到的三件事：

1. **准确解析需求方的真实产品标准** — 不是简单的关键词匹配，而是理解需求背后的工程意图
2. **识别供应方的真实能力边界** — 知道哪家供应商能生产什么标准的产品
3. **多产品组合匹配** — 一个需求涉及多个产品时，能通过多个符合标准的供应商组合完成

## 三、目标用户分析

### 3.1 三类核心用户

| 用户类型 | 核心需求 | 痛点 |
|---|---|---|
| **企业采购工程师** | 选对标准、快速找到合适供应商 | 翻手册选型、电话询价，2小时起；遇到错误标准不知道哪里错 |
| **生产厂家** | 产品展示、接到更多订单 | 线上展示为零，只能靠老客户；不知道如何数字化自己的产品能力 |
| **贸易商/经销商** | 快速报价、精准匹配供应 | 手工记库存、报价凭经验；遇到非标需求不知道找谁生产 |

### 3.2 第一批种子用户策略

**来源**：直接邀请贸易公司的老客户

**选择标准**：与贸易公司关系最熟、最愿意反馈的工程师/采购，10-20人

**理由**：
- 有信任基础，无需从零建立关系
- 反馈真实，不会为了客气而说好话
- 转化率高，有实际业务往来做黏性

## 四、产品价值分层

产品价值分三个层次，**从易到难，从免费到高利润**：

### 4.1 第一层：工具层（免费，快速聚人）

用户能直接感知、零门槛使用：

- **标准查询** — 标准号、规格、材质、强度等级、关联参数
- **专家解读** — 每条标准下方附专家注解：注意点、常见误区、替代方案
- **知识库** — 操作规范、常见问题、施工避坑指南

> **MVP 核心：标准查询 + 专家解读，打包成「工具 + 知识」产品**

### 4.2 第二层：系统层（付费产品化）

用户基数起来、信任建立后推出：

- **PFMEA 系统** — 紧固件失效模式与影响分析，提供模板和流程引导
- **装配管理系统** — 标准装配流程数字化，帮助企业落地 SOP

### 4.3 第三层：服务层（高利润，难复制）

这是最难被复制、客户愿意为「有人帮我做到」付高价的层次：

- **教练/顾问服务** — 帮企业落地 PFMEA 等管理环节
- **定制化标准方案** — 专家参与，为企业设计专属标准体系

> **关键判断：最值钱的是第三层，因为最难被复制**

## 五、商业模式三层结构

```
第一层：工具层（线上，可复制）
├─ 标准查询 ────── 免费/低价，快速获客
├─ 标准解读 ────── 解决理解误区
└─ 知识库 ───────── 操作规范、常见问题

第二层：系统层（软件，可产品化）
└─ PFMEA 系统 ──── 模板、流程引导、数据联动

第三层：服务层（人力，难复制但高利润）
└─ 教练/顾问服务 ─ 帮客户落地执行
```

## 六、MVP 功能边界（第一阶段，0-90天）

### 6.1 什么是 MVP？

MVP 不是「功能最少的产品」，而是「验证核心假设最快的产品」。

核心假设：
> **工程师用户愿意为「专家校正过的标准 + 配套解读」专门来这个平台**

### 6.2 MVP 功能清单

**P0（必须做）**

| 功能 | 说明 | 差异化体现 |
|---|---|---|
| 标准数据库 | GB/ISO/DIN 标准，支持多条件筛选 | 数据经专业纠正，不是搬运 |
| 标准详情页 | 展示标准参数 + 专家解读 | 每条标准附专家注解 |
| 全文搜索 | 关键词检索标准 | 支持标准号/规格/材质等维度 |

**P1（做了更好，第一批用户更愿意用）**

| 功能 | 说明 | 差异化体现 |
|---|---|---|
| 收藏夹 | 用户收藏常用标准 | 提升回访率 |
| 知识库入口 | 快速检索专家解读、装配指南 | 从工具层延伸到知识层 |
| 用户登录 | 记录使用历史 | 为后续个性化打基础 |

**P0 禁止做的（第一阶段不碰）**

- 询价/交易功能
- PFMEA 系统
- 供应商管理系统
- 任何需要多角色协作的功能

> **理由：第一阶段只验证一件事——用户是否真的需要「专家帮你看懂标准」这件事。如果这个不成立，后面的功能建在沙子上。**

## 七、战略路径

### 7.1 五步走

```
第一步：标准查询 ──── 工具入口，人人能用
        ↓ 快速迭代
第二步：接入知识库 ── 提供更多服务范围
        ↓ 用户基数 + 信任建立
第三步：建立 PFMA 模型 ── 从个人工具扩展为企业工具
        ↓ 平台规模效应
第四步：扩展贸易功能 ── 成为贸易中间件
        ↓ 现金流支撑
第五步：服务输出 ──── 顾问/教练服务，背书 + 发现隐藏机会
```

### 7.2 资源配置

| 资源 | 配置方式 |
|---|---|
| **技术团队** | 产品开发主力，人数充足 |
| **专家合伙人** | 时间灵活，主要用于内容生产（解读、知识库），不用于高频服务交付 |
| **种子用户** | 从贸易公司老客户中邀请 10-20 人 |

### 7.3 变现节奏

**第一阶段（免费验证）**
- 提供 100 条标准查询（GB 50条 + ISO 30条 + DIN 20条），确保各标准都有代表
- 超出部分可付费下载，或升级专业版

**第二阶段（订阅模式）**
- 个人版 ¥199/年：不限查询 + 对比分析
- 企业版 ¥2,999/年：多席位 + API + 定制标准

**第三阶段（服务转化）**
- PFMEA 系统 + 教练/顾问服务
- 高客单价，人力服务支撑

## 八、竞争格局与机会窗口

### 8.1 竞品现状

| 平台 | 能力 | 弱点 |
|---|---|---|
| 易紧通 | 标准多 | 数据陈旧，无解读 |
| 华人螺丝网 | 资讯强 | 非专业查询工具 |
| 工品一号 | 交易闭环 | 无工程深度内容 |
| **我们** | **数据准 + 专家解读** | **0 用户，从头建** |

### 8.2 市场数据

- 中国紧固件市场：**1593亿元**（2024），CAGR 4%~5%
- **70-80% 企业仍为纸质管理** — 数字化渗透率极低，蓝海明确
- 没有任何一个平台同时做到「标准库 + 工程工具 + 交易闭环」

## 九、数据展示策略

### 9.1 专家解读的呈现方式

**起点方案（已确认）**：每条标准下方附专家注解，包含：
- 这条标准在实际应用中的注意点
- 常见误区
- 替代方案（如有）

**后续演化**：根据用户行为数据，逐步将高频解读提炼为「标注」，在参数旁直接显示提示标记。

### 9.2 为什么不用标注作为起点

- 标注可能影响阅读流畅性，在没有建立信任前可能让用户困惑
- 解读内容的 SEO 价值更高，能带来自然搜索流量
- 先验证「用户是否在意专家解读」这件事，再决定投入标注体系

## 十、后续动作建议

1. **产品总监接手后**，建议优先输出以下内容：
   - 标准数据库 ER 图设计
   - 专家解读内容的编辑规范（保证多专家产出一致性）
   - 第一批种子用户的访谈提纲

2. **技术团队启动前**，建议确认：
   - 专家合伙人能稳定产出的解读内容量（每周多少条）
   - 现有知识文件向知识库迁移的优先级
   - 种子用户邀请的进度

3. **第一个里程碑建议**：
   > 上线包含 **GB 50条 + ISO 30条 + DIN 20条** 且每条附专家解读的标准库，邀请 **10 个种子用户**内测，收集 3 周反馈后决定下一步。
